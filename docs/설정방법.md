# 적용 및 재현 방법

## Open WebUI DB 연동
1. 접근 권한이 있는 계정으로 이 비공개 저장소를 clone합니다. 전체 소스와 수정 사항이 이미 포함되어 있습니다.
2. 이 작업의 기준 커밋은 `c38885a1a737da4968f157092f304f3b5481d0bf`입니다. 필요하면 별도 작업 브랜치를 만듭니다.
3. 원본 개발 환경 안내는 `docs/README.upstream.md`와 공식 개발 문서를 참고합니다. 다른 버전으로 올릴 때는 DB 연동 코드의 차이를 검토해 병합합니다.
4. 원본 프로젝트 안내대로 프런트엔드·백엔드 의존성을 설치합니다. 백엔드 환경에 `psycopg`가 필요합니다. Windows에서는 동기 연결을 별도 스레드에서 실행하는 구현을 사용했습니다.
5. PostgreSQL에 테스트용 DB를 만들고 `database/sample-data.sql`을 실행합니다. 이 SQL은 빈 DB를 기준으로 테이블을 생성합니다.
6. 조회 전용 계정을 준비하고 필요한 스키마·테이블에 조회 권한만 부여합니다. 실제 비밀번호는 저장소에 기록하지 않습니다.
7. Open WebUI 서버를 실행하고 관리자 계정으로 로그인합니다.
8. 워크스페이스 → 지식기반 → 생성에서 컬렉션을 만듭니다.
9. 컬렉션의 DB 연동 → 호스트·포트·DB명·조회 계정 입력 → 테이블 조회 → 미리보기 → 가져오기를 실행합니다.
10. 테이블별 CSV 내용과 표 미리보기, 다시 가져올 때 갱신되는지 확인합니다.
11. WEBUI_SECRET_KEY를 안정적으로 유지합니다. 첨부 시 DB 재조회를 위해 접속정보를 서버 DATA_DIR 안에 암호화해 저장하므로 이 디렉토리와 키를 저장소에 올리지 않습니다.
12. 채팅에서 DB 파일 또는 컬렉션을 선택하면 최신화가 끝난 뒤 첨부됩니다. 실패 시 연결을 확인하고 DB 연동에서 다시 가져옵니다. 기존 문서에 연결정보가 없을 때도 다시 가져와야 합니다.

## 샘플 영향도 분석 자료
`samples/obix-project/`에는 선택한 원본 소스 파일, `samples/3_DDL.ddl`에는 원본 DDL이 있습니다. 접속설정·의존성·빌드 결과물은 제외했습니다. `samples/obix-source/`는 지식기반에 넣은 모듈별 텍스트 묶음입니다.

저장소 루트에서 `python scripts/impact-analysis/write_impact_report.py`를 실행하면 정적 관계 분석 결과를 `outputs/impact-analysis/`에 생성합니다. Python 표준 라이브러리만 사용합니다. 6개 대화 시나리오는 별도 작성한 `docs/impact-analysis/영향도분석_결과_6개시나리오.md`입니다. 지식기반 등록은 완료됐지만 자동 검색 저장소/임베딩 및 답변 품질 검증은 미완료입니다.

## JetBrains AI Assistant
1. AI Assistant를 설치하고 필요한 라이선스 활성화 절차를 완료합니다. 검증 PC에서는 사용자 동의 후 무료 Educational Pack을 활성화했습니다. 모든 사용자에게 같은 자격이 있는 것은 아닙니다.
2. Providers & API keys에서 OpenAI-compatible 공급자를 선택하고 본인의 서버 Base URL을 입력합니다. 테스트에 사용한 모델은 `Qwen/Qwen3.8-27B-FP8`입니다.
3. 연결 테스트 후 Tool calling을 켭니다. Model Assignment의 Core features와 Instant helpers에 해당 모델을 지정합니다.
4. Model Context Protocol(MCP)에서 공식 `@modelcontextprotocol/server-filesystem`을 STDIO로 등록합니다. Node 실행 경로와 설치된 서버의 `dist/index.js`, 테스트 폴더의 절대 경로를 사용합니다. 접근 범위는 테스트 폴더 하나로 제한합니다.
5. Air의 New Session이 아니라 오른쪽 AI Chat을 열고 모델을 선택합니다. 검증 PC의 단축키는 Alt+Shift+1이었습니다.
6. MCP만 사용해 hello.txt의 `status: verified`를 `status: jetbrains-tested`로 수정하고 다시 읽도록 요청합니다.

## Cline CLI
1. 동일한 모델 공급자를 설정하고 사용하는 프로필의 `data/settings/cline_mcp_settings.json`에 같은 MCP 서버와 같은 허용 폴더를 등록합니다. 경로는 CLI 버전·프로필 설정에 따라 확인해야 합니다.
2. 작업 폴더를 테스트 폴더로 지정합니다. 자동 승인을 끈 상태로 시작합니다.
3. MCP만 사용해 `status: jetbrains-tested`를 `status: cline-tested`로 수정하고 다시 읽도록 요청합니다.
4. 도구 이름 `local-sample-files__*`와 실제 파일, 로그를 함께 확인합니다. 내장 파일 도구 사용과 MCP 사용을 구분합니다.

## 검증 유의사항
모델 서버 비용은 별도로 발생할 수 있습니다. CLI의 비용 $0 표시는 인프라 비용 무료를 의미하지 않습니다. 실제 프로젝트의 권한을 넓히거나 계정정보 파일을 테스트에 사용하지 않습니다.
